# 📰 منصة CollabX: فريق التحرير متعدد الوكلاء لإنتاج النشرات والتقارير الإخبارية

> **إطار عمل رائد ينظم فريقاً من الوكلاء المتخصصين (الباحث، الكاتب، المحرر) في مخطط سير عمل تعاوني لإنتاج نشرات إخبارية وتقارير استراتيجية جاهزة للنشر فورياً.**

> [!IMPORTANT]
> **حالة المشروع: محرك تحريري حتمي يعمل فعلياً، وليس نظام وكلاء مبنياً على نموذج لغوي.**
> بوابات الجودة حقيقية: درجة سهولة القراءة تُحسب فعلياً بمقياس Flesch Reading
> Ease، وتدقيق الحقائق يتتبع كل إحصائية واقتباس رجوعاً إلى ملف البحث، وهناك حلقة
> مراجعة محدودة بين المحرر والكاتب تعيد صياغة المسودات التي لا تجتاز البوابات.
> غير أن **الباحث ما زال بيانات ثابتة** — يُرجع النتيجتين نفسيهما لأي موضوع —
> و**الكاتب محرك قوالب وليس نموذجاً لغوياً**. ربط الوكلاء بنموذج لغوي هو العمل
> المتبقي. راجع جدول الحالة في `README.md`.

## 🌟 المزايا المؤسسية الرئيسية

1. **فريق تحريري متعدد الأدوار والتخصصات**:
   - **`ResearcherAgent`**: استكشاف المؤشرات والبيانات والإحصائيات والاقتباسات التنفيذية الموثقة.
   - **`WriterAgent`**: صياغة المقالات التحريرية والعناوين الجذابة والفقرات المترابطة.
   - **`EditorAgent`**: تدقيق الحقائق، وتقييم سهولة القراءة (Flesch-Kincaid)، وضبط النبرة والصياغة وتجهيز كود HTML.
2. **خط معالجة تعاوني بمراحل مُعرَّفة الأنواع مع حلقة مراجعة**: تمرير منظم للسياق بين الباحث والكاتب والمحرر. يعمل المحرر كبوابة: المسودة التي لا تجتاز بوابات القراءة أو التوثيق أو النبرة تُعاد إلى الكاتب بحدود أضيق. الحلقة محدودة العدد وتتوقف عند اجتياز البوابات أو نفاد الميزانية أو عدم حدوث أي تغيير. **ولا يفشل الطلب أبداً**: إذا نفدت الميزانية والبوابات ما زالت غير مجتازة، تُنشر النشرة مع `revision_required: true` ونقد يوضح كل بوابة أخفقت ومقدار الفارق.
3. **إخراج Markdown و HTML**: تحويل على مستوى الكتل فقط (بدون تنسيق داخلي أو قوائم). يتم تهريب محتوى النصوص، فلا يمكن لموضوع يحتوي على وسوم أن يتحول إلى HTML فعّال.
4. **استوديو تحريري تفاعلي ثنائي اللغة**: واجهة زجاجية عصرية تدعم العربية (RTL) بالكامل لمتابعة مراحل التحرير وقراءة النشرة النهائية.
